# Kabuby.com foundation and reconciliation: Waves 0–2

## Scope and invariant

This foundation preserves Kabuby Scout exactly as the protected existing surface. It does not change Scout source, routes, session/authentication behavior, Chrome extension integration, contracts, or read models. The `test/kabuby-foundation.test.mjs` baseline test compares its protected source regions to audited commit `17b65b2d8dc4f480751378ea419113e80f052021`.

## Wave 0 — false-reality isolation

The legacy Cazador, Price Monitor, eBay Connect, Predicción IA, and SaaS Platform are removed from primary navigation outside Scout. Their historical source remains available but they no longer present heuristic demand, opportunity, margin, repricing, inventory, or execution claims as current Kabuby truth. The legacy Radar is a non-connected read-only state, not `LIVE` or canonical opportunity scoring. Browser-held OpenAI configuration, direct OpenAI transport, and active raw GitHub MeLi cache consumption are removed from the active index path.

The Today fallback is intentionally `STALE_FALLBACK_NOT_CURRENT`: it contains no current executive decisions, recommendations, opportunities, or operational assertions. It is not cached as current evidence.

## Wave 1 — release governance

The in-repository GitHub Actions Pages deployment is neutralized. It now validates only an explicitly supplied source commit and preview URL; it does not deploy. `kabuby-ci.yml` supplies static syntax, frontend contract, secret-boundary, and Scout-source protection gates.

The desired authoritative route is:

```
GitHub source → Kabuby foundation CI → Cloudflare Pages preview → validation → explicit production promotion
```

Cloudflare Pages native integration remains an external administrative configuration. Its exact settings are not altered without Pages access. Until that configuration is reviewed and constrained, no production promotion is certified. The last audited public HTML integrity hash is `ee811b37c804f2cd7c397037c442ee608dc15f865e54ef7b3f2a0f5d9fb9664f`; it is the rollback content baseline, not a claim of current deployment lineage.

## Wave 2 — authenticated Physical projection

`kabuby-physical-read-only-projection/v1` is one fixed server-side, read-only projection contract. It cannot select provider, query, record, store key, or execution action. It projects the nine certified UI surfaces: Physical Command Center, opportunity Radar, protected Scout contract metadata, supply intelligence, economics/channel matrix, marketplace operations, portfolio, outcome learning, and settings/policies. The existing Gate1 runtime is V2-frozen; this foundation deliberately does not wire the projection into it or claim that a production endpoint is deployed.

Missing canonical server projection inputs become explicit `NO_*`/`UNKNOWN` states. No raw provider response, secret, token, browser credential, or commercial action is exposed. CM-07 is presented as `LEGITIMATELY_DEFERRED_NO_ELIGIBLE_REAL_CANDIDATE`; TA2-05 as `BLOCKED_REQUIRED_NATIVE_FIELD_UNAVAILABLE`.

The static shared browser client is GET-only and, once a non-V2 authenticated gateway is bound, uses authenticated reads with loading, error, empty, partial, stale, blocked, unknown, and unauthorized states. It contains no privileged credential and fails closed until a sanctioned route exists.

## Remaining external release blocker

Cloudflare Pages administrative access is required to verify and configure native Git integration, protected CI checks, preview restriction, explicit production promotion, and a deployment-id rollback target. No user-visible deployment is performed by this foundation.
